# SocialOps

> 開発者向けメモ: このリポジトリは、旧 AI ゲートウェイ系コードベースから、Web サイト内の総アカウントプールを中心にしたソーシャル運用プラットフォームへ移行中です。変更前に [PROJECT_GUIDE.md](PROJECT_GUIDE.md) を読んでください。

SocialOps は、Web サイト内の総アカウントプールに存在するソーシャルアカウントだけを扱う SaaS プラットフォームです。管理者はアカウントをインポートまたは実登録し、未割り当てアカウントをユーザーへ割り当てたり回収したりします。ユーザーのインポートは外部アカウント追加ではなく、X の `@xxx` のようなプラットフォームユーザー名で既存プール内の未割り当てアカウントを照合します。現段階ではフォロー、メッセージ、投稿、いいね、ログインチェックなどのタスク提出、検証、キュー投入、ログ、課金フレームだけを整え、実行ワーカーは後続で接続します。成功時のみ最終課金されます。

## 現在の方向性

- **総ソーシャルアカウントプール**: プール内アカウントだけを処理し、照合できない外部アカウントは保存、割り当て、実行、課金しません。
- **アカウント入庫**: 管理者インポート、既存ロジックによる重複排除、実登録、手動割り当て、未割り当てへの回収、ユーザーのプラットフォームユーザー名照合。複数候補に一致する曖昧な照合は拒否します。
- **タスク実行**: ユーザー向けのソーシャル操作タスクと今後の実行基盤。実行器未接続時は失敗として閉じます。
- **IP / プロキシ管理**: ユーザー専有の実行リソースを管理者の `/admin/proxies` ワークスペースで管理します。アカウントには安定した実行呼び出し用のデフォルトプロキシを保存でき、同一ユーザー自身のプロキシはそのユーザーの複数アカウントで使えます。アカウント回収時はデフォルトプロキシを消去し、IP / プロキシのテストは無料です。
- **実行課金**: 実際のソーシャル実行アクションは内蔵単価 `0.1`。アカウント/IP 管理操作は無料です。既存のサブスクリプション/ウォレット基盤を再設計せず再利用し、サブスクリプションの金額枠を優先し、不足分はウォレット残高から消費し、成功時のみ最終課金し、非成功時は返却/解放または未課金にします。
- **SaaS 基盤**: 認証、JWT 更新、OAuth ログイン、プロフィール、2FA、管理者、設定、公告、サブスクリプション、決済、残高チャージ、交換コード、クーポン、アフィリエイト。
- **組み込みフロントエンド**: Vue/Vite のビルド成果物を Go バイナリに `-tags embed` で組み込みます。

## 復元しないもの

SocialOps は AI ゲートウェイではありません。AI プロバイダールーティング、モデルチャネル、上流アカウント認証情報プール、モデル価格、トークン課金、ゲートウェイ監視、プロバイダー固有 OAuth / トークン更新フローは復元しません。

現段階では、アカウント購入フロー、実際のソーシャルプラットフォーム実行器、販売/レンタル専用状態、自動レンタル期限切れ、新しいウォレット/サブスクリプション課金体系、ユーザー自身のアカウントデータへの追加マスキングやアプリ層暗号化も先に実装しません。

## ローカルビルド

```bash
cd frontend
pnpm install
pnpm run build

cd ../backend
go build -tags embed -o socialops ./cmd/server
```

## 検証

```bash
make build
make test
make test-frontend
make secret-scan

cd backend && go test -tags=unit ./...
cd frontend && pnpm run typecheck && pnpm run build && pnpm run lint:check
```

## デプロイ

開発用イメージ:

```bash
cd deploy
docker compose -f docker-compose.dev.yml build
docker compose -f docker-compose.dev.yml up -d --no-build
```

ローカルのデータベースや Redis ボリュームを削除しないでください。削除はデータ破壊を意味します。
